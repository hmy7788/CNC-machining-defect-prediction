# CNC QA 절차

## 핵심 원칙: 존재 확인이 아니라 경계면 교차 비교

"파일이 생겼는지"가 아니라 "그 파일이 주장하는 대로 실제로 만들어졌는지"를 확인한다. 예를 들어 `cnc-preprocess`가 "실험 단위로 분할했다"고 기록했으면, 그 주장을 그대로 믿지 말고 실제 분할 코드/산출물을 열어 `No` 값이 train/val/test 사이에 겹치지 않는지 직접 확인한다.

## 점검 항목

### 1. 자동화된 센서 실행
```bash
ruff check .
python -m pytest tests/ -v
python scripts/check_report.py
python scripts/check_docs_drift.py
python scripts/check_structure.py
```
하나라도 실패하면 구체적 실패 내용(파일·라인·에러 메시지)을 그대로 재작업 요청에 포함한다.

### 2. 분할/전처리 순서 (cnc-preprocess 산출물 검증 시)
- 분할 기준이 실험(`No`) 단위 또는 시간 순서인지 — 행 단위 무작위 분할 여부를 코드에서 직접 확인.
- 정규화 통계량이 분할 이후, 학습 폴드에서만 계산됐는지.
- 오버샘플링/언더샘플링이 학습 폴드 내부에서만 적용됐는지.

### 3. 성능·수치 정합성 (cnc-model 산출물 검증 시)
- 보고된 수치가 다중 시드 평균인지, 단일 시드인지.
- 성능이 비정상적으로 높으면(예: AUC 0.98+) 위 2번 항목(분할/전처리 순서)을 먼저 재확인 — 원인이 해명되지 않으면 통과시키지 않는다.
- `reports/metrics.json`에 등록된 값과 `docs/experiments/NNN-model-*.md`에 적힌 값이 일치하는지.

## 판정과 재작업

- **통과**: 오케스트레이터에게 통과를 보고하고 다음 Phase로 진행하게 한다.
- **불합격**: 무엇이·왜 문제인지 구체적으로 적어 해당 생성 에이전트(`cnc-preprocess` 또는 `cnc-model`)에게 재작업을 요청한다. 같은 문제로 2~3회 넘게 반복되면 사용자에게 보고하고 판단을 구한다 (무한 재시도 금지).
- 새로 발견한 실패 패턴(이전에 없던 종류의 문제)은 `docs/failures/NNN-*.md`로 남기고 `docs/failures/INDEX.md`에 태그(`#data` `#eval` `#model` `#env` `#process` `#agent`)와 함께 추가한다.

## 후속 작업

"다시 검증해줘", "이번엔 통과했는지 확인해줘" 요청 시에도 이 스킬을 사용한다.

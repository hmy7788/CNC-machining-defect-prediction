# CNC 전처리 절차

## 왜 순서가 중요한가

이 데이터는 실험(`No`) 단위 시계열이다. 정규화 통계량이나 오버샘플링을 분할 전에 계산하면, 검증/테스트 폴드의 정보가 학습 과정에 새어 들어간다(데이터 누수). 이후 `cnc-model`이 비정상적으로 높은 성능을 보고하면 `cnc-qa`가 이 문서의 순서 위반부터 의심한다 — 애초에 위반하지 않는 게 재작업을 줄인다.

## 절차 (반드시 이 순서로)

1. **라벨 생성** — `data/raw/CNC 비식별화 원본데이터_1209/train.csv`에서 직접 만든다. 값에 정렬용 공백이 있으니 `skipinitialspace=True` 또는 `.str.strip()` 적용. `CNC 학습통합데이터_1209`의 `Y_*`는 쓰지 않는다 (`docs/decisions/001-data-source-strategy.md`).
2. **분할** — 실험(`No`) 단위 또는 시간 순서로 train/validation/(test)를 나눈다. 행 단위 `train_test_split(shuffle=True)` 같은 무작위 분할은 금지 — 같은 실험의 연속된 타임스텝이 train/test 양쪽에 섞이면 사실상 답을 보고 맞히는 것과 같다.
3. **정규화/스케일링** — 분할 이후, 학습 폴드에서만 통계량(평균/표준편차 등)을 계산하고 검증/테스트 폴드에 적용한다. 반대로 하지 않는다.
4. **오버샘플링/언더샘플링** — 적용한다면 학습 폴드 내부에서만. 검증/테스트 폴드에는 적용 금지 — 원본 분포 그대로 평가해야 실제 성능을 알 수 있다.
5. **피처 엔지니어링** — 시계열 특징(윈도우 통계, `Machining_Process` 단계별 집계 등)을 만든다면, 미래 시점 정보가 과거 시점 피처에 섞이지 않는지(시간 누수) 확인한다.

## 산출물

- `data/processed/`에 저장 (`data/raw/`는 절대 수정하지 않음).
- 어떤 실험(`No`)이 train/val/test 중 어디에 속하는지 명시적으로 기록 — 재현성과 QA 검증에 필요하다.
- `docs/experiments/NNN-preprocess-*.md`에 라벨 생성 로직, 분할 기준, 전처리 순서를 기록.

## QA 재작업 요청을 받으면

`cnc-qa`가 분할/순서 위반을 지적하면, 지적된 부분만 고치고 무엇을 왜 고쳤는지 기록에 추가한다. 같은 지적을 2회 이상 받으면 근본 원인(코드 구조 문제 등)을 다시 살핀다.

## 후속 작업

"전처리만 다시", "분할 기준 바꿔줘", "피처 추가해줘" 요청 시에도 이 스킬을 사용한다. 이전 `docs/experiments/NNN-preprocess-*.md`가 있으면 먼저 읽고 어떤 로직을 썼는지 확인한 뒤 변경분만 반영한다.

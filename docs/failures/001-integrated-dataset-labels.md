# 001. 학습통합데이터 Y 라벨 의미 역산 실패

**태그**: `#data`

## [해결됨 — 2026-09-04] 답을 찾음 (역산이 아니라 공식 문서에서)
`docs/03. Guidebook_CNC.pdf`(KAMP 공식 가이드북) 27~40쪽에 제작 절차가 그대로 나와 있었다.
아래에서 "실패"로 남겨둔 시도(행 순서 역산)는 실패한 게 맞지만, 정답은 다른 경로(공식 문서 정독)로
찾았다. 정답 요약 — 자세한 근거는 `docs/domain/glossary.md`의 "학습통합데이터 라벨 제작 방식(공식)"
절 참고:

- `Y_*`는 `tool_condition`이 아니라 **`machining_finalized` + `passed_visual_inspection`을 합친
  값**이다: 공정완료+합격=양품(0), 공정완료+불합격 또는 공정미완료=불량품(1).
- `X_train`은 양품 데이터를 앞에서부터 9,403행만 자르고(불량품 9,403행과 개수를 맞추려고) 이어붙인
  것 — 그래서 실험 1·2번은 순서가 유지되고 3번부터 어긋난다(9,403행 자르는 지점이 실험 중간이라서).
- `X_test`는 **남은 양품 데이터 전부**라서 `Y_test`가 전부 0인 게 당연한 설계다(버그 아님).

이 발견 이후에도 `docs/decisions/001-data-source-strategy.md`의 "Y_*를 라벨로 안 쓴다"는 결정
자체는 바뀌지 않는다 — 오히려 이 결정이 옳았던 이유가 명확해졌을 뿐이다.

## 시도한 날짜
2026-09-04

## 시도한 이유
`data/raw/CNC 학습통합데이터_1209/Y_train.csv`, `Y_test.csv`가 무엇을 예측하는 라벨인지 (`tool_condition`
인지 `passed_visual_inspection`인지) 알아내려고, `X_train.csv`가 25개 실험 CSV를 순서대로 이어붙인
것이라는 가정 하에 각 실험의 행 구간을 계산하고, 그 구간의 `Y` 값과 `train.csv`의 실험별 라벨을
대조했다.

## 실패 원인
- 실험 1, 2번은 누적 행 수 계산과 실제 데이터가 정확히 일치했다 (검증 완료).
- 하지만 실험 3번부터는 각 실험 파일의 `wc -l` 기준 행 수로 계산한 경계가 실제 데이터와 어긋났다
  (예상 위치의 데이터가 다른 실험의 값이었다). 즉 단순 순서 concatenation이라는 가정이 3번째 파일부터
  깨진다 — 파일별 행 수 계산에 오차가 있거나, 실제 이어붙이는 순서가 파일명 순서와 다르다.
- 이 상태로 무리하게 라벨을 매칭한 결과(`exp_06`, `exp_09`가 `worn`인데 `Y=1,0`, `exp_13`도 `worn`인데
  `Y=0,1`)는 서로 모순되어, `tool_condition` 단일 컬럼으로는 설명되지 않았다.

## 현재 대안
`docs/decisions/001-data-source-strategy.md` 참고 — 통합데이터의 `Y_*`를 쓰지 않고 원본 `train.csv`에서
라벨을 직접 만든다.

## 에이전트 지침
`학습통합데이터`의 `Y_train.csv`/`Y_test.csv` 값을 행 순서로 다시 역산하려고 시도하지 않는다 (그
방식은 이미 실패한 접근이다 — 위 "해결됨" 절 참고, 답은 `docs/03. Guidebook_CNC.pdf`에 있다).
라벨이 필요하면 원본 `train.csv`에서 새로 만들 것.

# 001. 학습통합데이터 Y 라벨 의미 역산 실패

**태그**: `#data`

## 시도한 날짜
2026-09-04

## 시도한 이유
`data/raw/CNC 학습통합데이터_1209/Y_train.csv`, `Y_test.csv`가 무엇을 예측하는 라벨인지 (`tool_condition`
인지 `passed_visual_inspection`인지) 알아내려고, `X_train.csv`가 25개 실험 CSV를 순서대로 이어붙인
것이라는 가정 하에 각 실험의 행 구간을 계산하고, 그 구간의 `Y` 값과 `train.csv`의 실험별 라벨을
대조했다.

## 실패 원인
- 실험 1, 2번은 누적 행 수 계산과 실제 데이터가 정확히 일치했다 (검증 완료).
- 하지만 실험 3번부터는 각 실험 파일의 `wc -l` 기준 행 수로 계산한 경계가 실제 데이터와 어긋났다
  (예상 위치의 데이터가 다른 실험의 값이었다). 즉 단순 순서 concatenation이라는 가정이 3번째 파일부터
  깨진다 — 파일별 행 수 계산에 오차가 있거나, 실제 이어붙이는 순서가 파일명 순서와 다르다.
- 이 상태로 무리하게 라벨을 매칭한 결과(`exp_06`, `exp_09`가 `worn`인데 `Y=1,0`, `exp_13`도 `worn`인데
  `Y=0,1`)는 서로 모순되어, `tool_condition` 단일 컬럼으로는 설명되지 않았다.

## 현재 대안
`docs/decisions/001-data-source-strategy.md` 참고 — 통합데이터의 `Y_*`를 쓰지 않고 원본 `train.csv`에서
라벨을 직접 만든다.

## 에이전트 지침
`학습통합데이터`의 `Y_train.csv`/`Y_test.csv` 값을 어떤 컬럼의 인코딩인지 다시 역산하려고 시도하지
않는다 (이미 실패한 접근이다). 라벨이 필요하면 원본 `train.csv`에서 새로 만들 것.

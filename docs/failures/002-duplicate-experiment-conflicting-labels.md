# 002. 중복 실험 파일이 서로 다른 라벨을 갖고 있음

**태그**: `#data`

## 발견한 날짜
2026-09-04 (EDA 중 발견 — `docs/experiments/001-eda-cnc-baseline.md` 참고)

## 무엇을 발견했나
`data/raw/.../CNC Virtual Data set _v2/`의 25개 실험 CSV를 MD5 해시로 비교한 결과, 두 쌍이
바이트 단위로 완전히 동일한 파일이다:

- `experiment_14.csv` == `experiment_24.csv`
- `experiment_19.csv` == `experiment_25.csv`

그런데 `train.csv`에 적힌 라벨은 같은 파일인데도 서로 다르다:

| No | tool_condition | passed_visual_inspection |
|---|---|---|
| 14 | worn | yes |
| 24 | unworn | yes |
| 19 | worn | no |
| 25 | worn | yes |

같은 센서 데이터에 모순된 정답이 붙어 있는 셈이다.

## 왜 문제인가
- 이 두 쌍을 그대로 학습에 넣으면, 완전히 같은 입력(X)에 서로 다른 라벨(Y)을 학습시키는 것과
  같다 — 모델이 배울 수 없는 노이즈를 강제로 주입하는 셈이고, 어느 라벨이 "진짜"인지 원본 데이터
  만으로는 알 수 없다.
- 실험 단위 분할을 하더라도, 이 쌍이 각각 train/test로 쪼개져 들어가면 (거의) 동일한 샘플이 양쪽에
  다 있는 것과 같은 효과가 나서, 성능이 실제보다 낙관적으로 보일 수 있다 — 지금까지 CLAUDE.md에
  기록한 "행 단위 무작위 분할 금지"와는 다른 종류의, 실험 단위 분할에서도 발생 가능한 누수 경로다.

## 현재 결론 (미확정)
어느 라벨이 맞는지 판단할 근거가 이 데이터 안에는 없다. `docs/03. Guidebook_CNC.pdf`(KAMP 공식
가이드북)를 정독했지만 이 중복/충돌을 직접 언급하는 내용은 없었다 — 다만 가이드북 13쪽에 실린
공식 실험별 행 수가 우리가 잰 값과 정확히 일치하고, 14번=24번, 19번=25번의 행 수도 거기서 동일하게
나온다. 즉 **이 중복은 우리 다운로드나 처리 과정의 문제가 아니라 KAMP 원본 데이터 자체의 특성**임이
재확인됐다 — 여전히 어느 라벨이 맞는지는 알 수 없다.

**[2026-09-04 갱신] 타겟을 뭘로 잡느냐에 따라 충돌 여부가 달라진다는 걸 확인했다**
(`docs/domain/glossary.md`의 "학습통합데이터 라벨 제작 방식(공식)" 참고, 공식 라벨은
`tool_condition`이 아니라 `machining_finalized`+`passed_visual_inspection` 조합이다):

| 쌍 | tool_condition | machining_finalized | passed_visual_inspection | 공식 라벨(양품/불량) 기준으로 충돌? |
|---|---|---|---|---|
| 14 | worn | yes | yes | 양품 |
| 24 | unworn | yes | yes | 양품 (**14와 동일 — 충돌 없음**) |
| 19 | worn | yes | no | 불량품 |
| 25 | worn | yes | yes | 양품 (**19와 충돌**) |

- **`tool_condition`을 타겟으로 쓰는 우리 프로젝트(002-preprocess) 기준으로는 두 쌍 다 여전히
  진짜 충돌**이다 — 지금 결정(둘 다 제외)은 그대로 유효하다.
- 다만 향후 "공식 defect 라벨"(finalized+passed 조합)로 타겟을 바꾸는 실험을 한다면, (14,24)는
  라벨이 같아서 충돌이 아니게 되고 (19,25)만 실제로 처리가 필요한 충돌로 남는다는 점을 참고할 것.

## 에이전트 지침
- `cnc-preprocess` 단계는 이 두 쌍(14/24, 19/25)을 어떻게 처리할지 명시적으로 결정하고 그 근거를
  `docs/decisions/` 또는 해당 실험 기록에 남긴 뒤에 진행한다 — 조용히 둘 다 포함시키지 않는다.
- 이 문제를 "새로 발견"한 것처럼 다시 조사(해시 비교)할 필요는 없다 — 이미 확인된 사실이다. 대신
  "어떻게 처리할지" 결정에 집중한다.
- 통합데이터(`CNC 학습통합데이터_1209`)를 참고할 때도 이 중복이 그대로 들어있어 행 수가 부풀려져
  있다는 점을 감안한다.

# 002. 중복 실험 파일이 서로 다른 라벨을 갖고 있음

**태그**: `#data`

## 발견한 날짜
2026-09-04 (EDA 중 발견 — `docs/experiments/001-eda-cnc-baseline.md` 참고)

## 무엇을 발견했나
`data/raw/.../CNC Virtual Data set _v2/`의 25개 실험 CSV를 MD5 해시로 비교한 결과, 두 쌍이
바이트 단위로 완전히 동일한 파일이다:

- `experiment_14.csv` == `experiment_24.csv`
- `experiment_19.csv` == `experiment_25.csv`

그런데 `train.csv`에 적힌 라벨은 같은 파일인데도 서로 다르다:

| No | tool_condition | passed_visual_inspection |
|---|---|---|
| 14 | worn | yes |
| 24 | unworn | yes |
| 19 | worn | no |
| 25 | worn | yes |

같은 센서 데이터에 모순된 정답이 붙어 있는 셈이다.

## 왜 문제인가
- 이 두 쌍을 그대로 학습에 넣으면, 완전히 같은 입력(X)에 서로 다른 라벨(Y)을 학습시키는 것과
  같다 — 모델이 배울 수 없는 노이즈를 강제로 주입하는 셈이고, 어느 라벨이 "진짜"인지 원본 데이터
  만으로는 알 수 없다.
- 실험 단위 분할을 하더라도, 이 쌍이 각각 train/test로 쪼개져 들어가면 (거의) 동일한 샘플이 양쪽에
  다 있는 것과 같은 효과가 나서, 성능이 실제보다 낙관적으로 보일 수 있다 — 지금까지 CLAUDE.md에
  기록한 "행 단위 무작위 분할 금지"와는 다른 종류의, 실험 단위 분할에서도 발생 가능한 누수 경로다.

## 현재 결론 (미확정)
어느 라벨이 맞는지 판단할 근거가 이 데이터 안에는 없다. KAMP 원본 배포 페이지나 공개된 동일
데이터셋(Kaggle "CNC Mill Tool Wear")의 별도 안내가 있는지 확인이 필요하며, 그런 확인 없이
"14번이 맞다" 식으로 임의 판단하지 않는다.

## 에이전트 지침
- `cnc-preprocess` 단계는 이 두 쌍(14/24, 19/25)을 어떻게 처리할지 명시적으로 결정하고 그 근거를
  `docs/decisions/` 또는 해당 실험 기록에 남긴 뒤에 진행한다 — 조용히 둘 다 포함시키지 않는다.
- 이 문제를 "새로 발견"한 것처럼 다시 조사(해시 비교)할 필요는 없다 — 이미 확인된 사실이다. 대신
  "어떻게 처리할지" 결정에 집중한다.
- 통합데이터(`CNC 학습통합데이터_1209`)를 참고할 때도 이 중복이 그대로 들어있어 행 수가 부풀려져
  있다는 점을 감안한다.

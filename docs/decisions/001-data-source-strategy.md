# 001. 라벨은 원본 실험 데이터에서 직접 만든다

## 상태
확정 (2026-09-04)

## 배경
`data/raw/CNC 학습통합데이터_1209/`에는 이미 만들어진 `X_train/X_test/Y_train/Y_test` (헤더 없는 flat
CSV)가 들어있어서, 이걸 바로 모델 학습에 쓰고 싶은 유혹이 있다.

## 결정
`Y_train.csv`/`Y_test.csv`를 정답으로 그대로 쓰지 않는다. 라벨이 필요하면
`data/raw/CNC 비식별화 원본데이터_1209/train.csv`(실험 25건의 `tool_condition`,
`machining_finalized`, `passed_visual_inspection`)에서 직접 만든다.

## 이유
- `Y_test.csv` 13,242행이 전부 같은 라벨이다 (`docs/failures/001-integrated-dataset-labels.md` 참고).
  이 상태로는 테스트 성능을 신뢰할 수 없다.
- `Y_train.csv`는 정확히 9,403:9,403으로 완벽하게 균형 잡혀 있어, 원 분포가 아니라 리샘플링된 결과로
  보인다.
- `X_train.csv`/`X_test.csv`가 25개 실험 CSV를 순서대로 이어붙인 것까지는 행 수(32,048)로 확인했지만,
  실험 3번째 파일부터는 경계가 어긋나서 "몇 번째 실험이 어느 행 구간인지"를 역산으로 신뢰할 수 없다.
  즉 `Y_*` 라벨이 어떤 컬럼을 인코딩한 것인지 검증할 방법이 없다.

## 포기한 대안
- `학습통합데이터`의 `Y_*`를 그대로 신뢰하고 사용: 위 이유로 기각.

## 결과
전처리 코드를 짤 때는 `experiment_XX.csv` + `train.csv`에서 실험 단위 라벨을 만들고, 필요하면 그 라벨을
해당 실험의 모든 타임스텝 행에 broadcast하는 방식으로 새로 만든다. 에이전트는 `학습통합데이터`의 `Y_*`
파일을 라벨 소스로 제안하지 않는다.
